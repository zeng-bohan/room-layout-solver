# 设计文档

本文档记录布局求解器的关键设计决策、几何判定细节、搜索策略与确定性论证。
约束的业务含义见 [README](../README.md#3-约束建模)，本文聚焦"为什么这么做"。

## 1. 问题形式化

**输入**：多边形轮廓 `P`（逆时针折线）、门（线段 + 内外开标志）、物品集合
`{(name, L×W)}`，其中 `fridge` 带开门边净空约束。

**输出**：每件物品的中心点（原始坐标系）与旋转角，或 `feasible: false`。

**约束分层**：

- 硬约束：轮廓包含、物品互斥（允许贴触）、门区避让、冰箱开门边净空；
- 软偏好（题面："空间充足时优先所有物品均贴墙"）：建模为两阶段搜索——先在
  "全部贴墙"的强约束下求解，成功则天然满足偏好；失败才降级放开。

把软偏好转成"分阶段的硬约束"而不是目标函数，好处是**解的语义可解释**：
结果里 `allItemsWallFlush: true` 直接回答"是否做到了全部贴墙"，
`fridgeDoorClearanceMm` 直接回答"给冰箱留了多少净空"。

## 2. 几何原语与精度策略

全部几何在 `layout_solver/geometry.py`，只依赖标准库 `math`。

### 2.1 点在多边形内：even-odd 射线法

奇偶规则实现（`point_in_polygon`）。对凹多边形（example4 的凹槽）天然正确。

### 2.2 线段相交：只算"真穿越"，共线不算

`segments_properly_cross` 用四叉积符号判定严格相交，**共线/端点接触返回 False**。
这是整个求解器最关键的一处判定：贴墙摆放时矩形边与轮廓边**完全重合**，
若把共线当相交，所有贴墙解都会被误杀。区分规则：

- 边与轮廓边共线重叠（贴墙、贴门沿）→ 合法；
- 边以非零角度横穿轮廓边 → 非法。

### 2.3 矩形互斥：OBB SAT，允许贴触

`rect_overlap` 用分离轴定理做旋转矩形（OBB）严格重叠检测，投影区间**闭区间
相等不算重叠**——两件货架背靠背贴合是合法布局。

### 2.4 容差体系

| 位置 | 容差 | 方向 |
| --- | --- | --- |
| 求解器：物品相对轮廓 | 收缩 0.5mm 后做包含判定 | 放宽（贴边可放） |
| 内置校验器：物品相对轮廓 | 内缩 1.0mm 后做包含判定 | 收紧 |
| 独立交叉校验：物品四边 | 各边收缩 0.5mm + 内部取样 | 独立口径 |
| 贴墙判定（评分/校验） | 接触长度阈值 1mm | — |

要点：**求解器的放行口径必须比校验器更严或相等**，否则会出现"求解器放、
校验器杀"的抖动。这里求解器收缩 0.5mm < 校验器内缩 1.0mm，留了 0.5mm 的
安全带，浮点误差（1e-9 量级）远够不着。

### 2.5 角度：聚类出允许集，吸附按 mod 360

- 允许角度集：从轮廓边方向聚类（0.5° 容差），每条墙贡献 `θ` 与 `θ+90°` 两个
  朝向族，接近 0/90° 的墙精确吸附——example1 的斜墙自动得到 15.85°/105.85° 族。
- **mod 180 陷阱**：矩形占位在 mod 180 下对称，但冰箱开门边方向在 90° 与 270°
  下不同。输出吸附角度必须按 mod 360 处理（`Problem.snap_angle`，6 位小数内
  精确匹配墙角），否则会把 270° 吸附成 90°，门边朝向反 180°。

## 3. 搜索策略

### 3.1 两阶段 × 三档净空

```
for wall_only in (True, False):          # 阶段 A：全部贴墙 → 阶段 B：放开
    for level in (1220, 610, 2):         # 净空梯子：整门扇 → 半门扇 → 仅禁贴触
        搜索成功 → 返回（并报告阶段与档位）
```

- 阶段 A 命中即得 `allItemsWallFlush: true`；4 个示例全部在阶段 A 解决。
- 净空梯子逐档降级并**如实报告**实际档位（`fridgeDoorClearanceMm`），
  不假装给足了整门扇深度。

### 3.2 候选生成

每个搜索节点为当前物品生成三类候选（`Solver._candidates`）：

| 来源 | 阶段 | 说明 |
| --- | --- | --- |
| 贴墙滑移 | A + B | 沿每面墙以 50mm 步幅滑动，两种朝向；**补贴墙末端精确位**（步进会错过最后一个贴边位置） |
| 贴物对接 | 仅 B | 沿已放物品四边以 50mm 步幅向外对接，形成成排布局 |
| 自由网格 | 仅 B | 250mm 网格兜底，评分最低 |

候选去重：位置按 25mm 桶、角度按 45° 桶粗粒度去重，砍掉近重复候选。

**评分**：`(贴墙接触长度 + 0.3 × 贴物接触长度, −包围盒增量)` 降序。
直觉：先靠墙、再成排、最后少占新地方；0.3 是"贴物"相对"贴墙"的折扣，
保证阶段 B 里贴墙候选永远优先于贴物候选。

**先过滤后打分**：候选先过 `_fits` 可行性过滤，幸存者再评分排序。
稳定排序保证幸存者之间的相对顺序与"先排序后过滤"完全一致，试放序列不变、
结果逐字节相同；而打分是 O(候选数 × 墙数)，绝大多数候选过不了 `_fits`，
过滤前置把 example1 的求解时间从 68s 降到 14s（5×）。

### 3.3 回溯与剪枝

DFS 逐件放置，失败回溯。剪枝一条：**剩余物品面积之和 > 轮廓面积 − 门区面积 −
已用面积** 时必然无解，直接剪。节点预算 150k，达到上限如实返回 `feasible: false`。

### 3.4 确定性（重要）

**搜索预算只按节点数计，不含任何墙钟判断。** 背景：最初版本带 20s 时钟截断，
实测发现同一输入在不同速度的运行下输出不同——慢的运行会在第一阶段搜索中途
被时钟截断，错过全净空解，落到下一档（example2 曾稳定复现 610 vs 1220 两种
结果）。对布局工具这是硬伤：README 里的图必须能复现。

修复后验证：同机连跑 4 次，4 个示例的 result.json 逐字节一致
（`md5sum` 校验）。确定性依赖三件事：

1. 预算只看节点数（整数计数）；
2. 所有排序使用稳定排序、键为确定值；
3. 集合（`set`）只用于去重判断，不参与遍历顺序敏感的逻辑。

## 4. 冰箱开门净空的建模

- 开门边约定为冰箱 **length 边的局部 +y 侧**；搜索枚举 4 个朝向，等价于让算法
  自行选择哪一侧做开门边。
- 净空条：开门边外侧 `depth × length` 的矩形（`Solver._fridge_strip`）。
  两重约束：净空条必须**整体落在房间内**（所以开门边不许贴墙），且条内不得有
  任何其他物品。
- 三档 `depth`：整门扇摆动深度（fridge length，例题 1220）→ 半门扇（610）→
  仅禁贴触（2mm）。每档重建候选重新搜索，报告实际档位。

## 5. 门区

- 门沿线向房间内侧生成 2mm 薄条禁入区（门板厚度级别的物理避让）；
- `isOpenInward=true` 时额外生成 N×N 门扇摆动方块（N=门宽），居中放在门线
  内侧（`Problem._build_door_zones`）。内法线方向用 PIP 判定，不依赖输入顶点顺序。

## 6. 验证策略（四层）

| 层 | 捕什么错 |
| --- | --- |
| `tests.py` 冒烟测试 | 端到端行为回归：可行 / 不可行 / 门区阻塞 / 净空回退四类用例 |
| `layout_solver/validate.py` | 每次求解后对结果**重新推导**全部约束，逐条 PASS/FAIL |
| `scripts/independent_check.py` | 与主实现**零共享代码**（自己实现射线法 PIP、取样 + 叉积混判、独立推导门区），捕获"实现与校验器共用同一套错误假设"的系统性风险 |
| CI（3.8 / 3.12 矩阵） | 以上全部 + ruff lint/format，push 与 PR 均触发 |

## 7. 已知取舍

- **候选步长是启发式**：50mm 步进 + 末端精确位在实践中足够（4 例全得全贴墙解），
  但理论上不完备——步进位形之间可能存在更优解。要完备需要转成精确算法
  （如 MIP/约束规划），对题目规模是杀鸡用牛刀。
- **内开门净空取 N×N**：按题面主述；输入说明中的"1x1"理解为 N=1 的特例。
- **净空梯子降级是全局的**：降档后整个搜索用新档位重来，而不是局部混合
  （冰箱附近 1220、别处 610 这类解不会出现）——语义更简单，也更好解释。
- **门区保守处理**：外开门也保留 2mm 门沿薄条；对推拉门/外开门场景偏保守，
  不会产出门边贴物品的争议布局。

## 8. 性能实测

| 示例 | 物品数 | 优化前 | 优化后 | 说明 |
| --- | :---: | --- | --- | --- |
| example1 | 8 | 68.3 s | **13.6 s** | 斜墙 + 8 件，搜索树最大 |
| example2 | 8 | 19.2 s | **4.9 s** | 第一阶段即命中全净空解 |
| example3 | 9 | 0.9 s | **0.8 s** | 内开门 |
| example4 | 6 | 0.3 s | **0.2 s** | 凹槽轮廓 |

（Python 3.12 / Windows / 笔记本 CPU；优化指"先过滤后打分"。）

热点在 `_fits` 的 OBB SAT 与轮廓包含判定，如需进一步提速的方向：
候选按评分截断 top-K、SAT 前做包围盒粗筛、几何原语向量化。
当前规模（≤10 件）下没有必要。
